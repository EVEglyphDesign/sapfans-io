# GitHub-communities engagement lane

`EgD-SAPF-003` · Key ID `EgD-KEY-2026-07`

**Where SAPfans.io meets the practitioner communities that already exist**, without forking them.

The [Additive Doctrine](../paper/ADDITIVE-DOCTRINE.md) is explicit: *we do not fork the community.* This lane names the communities we do want to be in useful contact with, states what we bring to each, and states what we will not do.

## The communities

## The touch-point pattern

When SAPfans.io wants to appear in one of these communities:

1. **Bring an artefact, not an opinion.** A repository, a reproducible finding, a PR, a working sample. Never a "you should be doing this" comment with no code behind it.
2. **Credit named.** `EVEglyphDesign / SAPfans.io — <path in repo>`. Never anonymous, never under an alias.
3. **Link back to the canonical location** in this repository. The community platform hosts the conversation; the repository holds the record.
4. **Never edit-war.** If a community disagrees with an artefact we contributed, we take our copy home and iterate. Their space, their rules.

## Register of engagements

Every material contribution to another community — a PR, an issue, a sample repository, a talk proposal — is logged in [`REGISTER.md`](REGISTER.md) with the date, the destination, the artefact link, and the disposition.

That register is the honest picture of what SAPfans.io has actually brought to the wider commons, separate from what it has published on its own surface.
